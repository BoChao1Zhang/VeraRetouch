### 1.3 `mlp_wide` 这个对照到底在挡什么

**它挡的是审稿人/mentor 必问的那句：「你换了个大 100 倍的东西，是不是只是参数多了？」**

`mlp_wide` = **和 `mlp` 逐行相同的结构，只把 `width` 从 128 调到 880**（`model_rdg.py:497-498`，`MLPGen` 里 width 是唯一的 knob，`model_rdg.py:325-328`），使其参数量 4,933,244 **略高于** G-Lite 的 4,447,846（+10.9%）。于是就有了一个**同参数量、同数据、同配方、同渲染核心、同 tokenizer、同天花板**的四臂对照：

| 对照 | 参数比 | 收敛后 val_img ΔE00 p50 | 结论 |
|---|---|---|---|
| `mlp_wide` 4.93M vs `mlp` 0.25M | 19.6× | 7.116 vs 9.057 | 加宽 MLP 有用，但只买到 **−21.4%** |
| **`glite` 4.45M vs `mlp_wide` 4.93M** | **0.90×（transformer 更小）** | **3.610 vs 7.116** | **−49.3% / +5.556 dB** |

**这是唯一一条不依赖任何门槛线位置、也不随训练步数翻转的证据。** REPORT.md §12.1a（`REPORT.md:439-455`）自己撤回过一句「MLP-Wide 差 0.33 个百分点没过 15% 门」的 punchline，理由是那句话是 step-4000 的切片、step 5000 起就翻了——所以**汇报时不要讲门槛，要讲这条同参数量对照**。

### 1.4 transformer 侧的要件（PLAN §1.4 逐条落实，全部可指到行）

| 要件 | 实现 | 出处 |
|---|---|---|
| **N 个 primitive query + 1 个 global query** | `self.n_q = self.N + 1`；`query` shape (1, 49, d)；输出时 `h[:, :N]` 走 prim_head、`h[:, N]` 走 glob_head | `model_rdg.py:444-445, 464-466` |
| **K/V = patch token + 4 个 register token** | `kv = cat([kv_proj(tok) + PE, register.expand(B,-1,-1)], dim=1)` | `model_rdg.py:449, 475-478` |
| register 的文献依据 | Darcet et al., **arXiv:2309.16588**，NOTES 记「已打开原始来源核实」 | `model_rdg.py:23-24`；`REPORT.md:50-51` |
| **learnable Fourier 位置编码，加在 key 上** | `kv = kv + self.pe(...)`，**只加在 kv，不加在 query**；频率是 `nn.Linear(2, 32, bias=False)` 学出来的，init `std=8.0` | `model_rdg.py:381-401, 476` |
| **ModLN，每子层独立参数，由 style code 驱动** | `DecoderLayer` 里 n1/n2/n3 **三个各自独立的 `ModLN`**；`ModLN` = `LayerNorm(elementwise_affine=False)` + 零初始化 `Linear(style→2d)` 出 (scale, shift) | `model_rdg.py:362-378, 404-417` |
| **energy routing 在 {L/2, 3L/4, L}，带熵下界** | 三处 tap 用 `softmax(route_logit)` 加权融合；`route_entropy()` 回给 loss 做 `relu(h_min − H)` 惩罚；**每个 tap 另有一个 aux head** | `model_rdg.py:454-458, 468-470, 480-488`；loss 见 `train_rdg.py:339-341` |
| cross-attn 只在指定层 | `DecoderLayer(..., cross = i in cross_set)`，非指定层没有 cross_attn 模块（参数量上就少 690,432） | `model_rdg.py:450-453, 410-414` |
| **未实例化的部分（诚实登记）** | PLAN §1.4 token 清单里的 **5 个 mask token 与 1 个 1D 曲线 token 没有建**——Stage-1 的 cube 目标不监督它们，建了就是无监督死 token | `model_rdg.py:432-435`；`REPORT.md:53` |

### 1.5 输出头的参数化约束（红线三件套所在地）

`ParamHead.forward`（`model_rdg.py:186-215`），**加固档（默认）**：

| 量 | 参数化 | 意图 |
|---|---|---|
| `mu_i` | `anchor_i + (1/3)·tanh(z)` | anchor 来自 Stage-0 k-means（384 个 P-train LUT 拟合 μ 的 k-means），半径 1/3 |
| `sigma_i` | **`0.02 + 0.48·sigmoid(z)`** | **禁裸 exp**（红线）；极端 logit 下实测夹在 [0.0200, 0.5000]（`ci_checks_rdg.json :: results[3].detail`） |
| `off_i` | `0.1·z` | Cholesky 次对角 |
| `M_i` | `I + 0.1·z` | 局部仿射，identity-centered residual |
| `b_i` | `0.1·z` | |
| `o_i` (opacity) | `sigmoid(z − 2)` | 初值偏小 |
| `g_i` (existence gate) | `sigmoid(z + 4)` | 初值偏大 |
| **`G`（全局仿射）** | **`0.1·z` ⇒ 零初始化时 G = 0，不是 I** | **红线**：写成 `I + ΔG` 与归一化的 `q_i` 联立会给出 `f(x) = 2x`；实测 ‖G‖ = 0.0（`ci_checks_rdg.json :: results[2].detail`） |
| `c` | `0.1·z` | |

**`--free` 对照臂把这三件事全部去掉**（`model_rdg.py:193-202`）：`mu = z`（不锚定）、`sigma = exp(z).clamp(1e-3, 10)`（**裸 exp**，实测能冲到 10.0，`ci_checks_rdg.json :: results[4].detail`）、`G = z + I`（**G = I 的反模式**）。**这是 PLAN 明写的必做对照，不是我们额外加的**。

> `gate` 为什么乘在混合分子上而不是 payload 上：零初始化时每个 `g_i` 都是同一个 `sigmoid(4)`，作为公共因子在归一化里约掉、恒等保持；若做成 payload gate 则 `f(x) = 0.982x`，ΔE00≈1，恒等 CI 直接挂。见 `model_rdg.py:80-84`。

**「方差比」有两种读法，本实验预注册了两种并都报**（`NOTES.md` §6 决策 6）：
- **主：`var_ratio`** = 预测变换在**样本间**的方差 / 目标变换在样本间的方差，同一组色上算。塌陷成「一张平均 LUT」时 → 0。定义在 `train_rdg.py:157-162`。
- 副：`var_explained` = 1 − MSE/Var_between（R² 式），同处。

> ⚠ **这个 `var_ratio` 与 §5 里 MCQ 的 `var_ratio` 不是同一个量**，切勿混引。见 §5.1。

### 1.8 天花板的定义（这是「还有多少路没走完」的分母）

**定义**：把同一批 z 从「预测」改成「**逐 LUT 自由优化**」——同一套 `ParamHead`、同一个 `render`、同一套 anchor、同一套色彩口径、同一份 ΔE00 代码。即一个容量无穷、无泛化负担的 oracle 生成器。脚本 `tools/fit_ceiling.py`。

| 天花板版本 | anchor | P-train ΔE00 p50 | PSNR | P-val ΔE00 p50 | PSNR | alive |
|---|---|---|---|---|---|---|
| `runs/ceiling_kmeans`（**正式**，与各臂同 anchor） | Stage-0 k-means | **0.5191** | **43.650** | **0.5205** | 43.690 | 0.690 |

**唯一的负结果 L6（信息性）**：L6 用两张重叠软掩膜 + 顺序双变换，交给估计器的是 `s = max(a,b)`。Δ_arm 只有 **3.66 dB**（局部级最低），**臂式相对嵌套式只 +0.31 dB**（L1 是 +14.3、L2 是 +16.7），4D 后绝对 PSNR 卡在 **39.78 dB**。`max(a,b)` 把「哪个区域」这一位信息压掉了 ⇒ **单标量第四轴的表达秩上限**，不是估计器问题。**这是 RD-F 双轴 5D 臂的定量立项证据**（`REPORT.md:431-453`）。

**是什么**：`losses.l_hc` 在**绝对 CIELab** 里算（a,b ~ O(100)，∂Lab/∂rgb ~ O(10²–10³)），而 `L_rec` 在 **RGB[0,1]** 里算。论文的 `L = L_rec + 10·L_hc` 于是让附加项的梯度**完全淹没**重建项。

**怎么发现的**——逐项隔离，9 个按 rec PSNR 分位取的 LUT（跨 36.2–54.7 dB 全区间）× 20 ep × N=32，同种子配对（`metrics.json :: task1_ingredient_isolation.arms.*`）：

| 臂 | 目标 | PSNR | **Δ vs rec** | ΔE00 | 梯度尖峰 >100× | 收敛 L_rec | 收敛 L_hc |
|---|---|---:|---:|---:|---:|---:|---:|
| `rec` | L_rec | 42.627 | — | 0.7394 | 0 | 0.005441 | 0.018419 |
| **`hc`** | +**10**·L_hc | **31.901** | **−10.726** | 2.3271 | **11** | 0.022253（**差 4.1×**） | 0.002626（**好 7.0×**） |
| `sparse` | +0.001·R_sparse | 42.586 | −0.041 | 0.7403 | 0 | 0.005475 | 0.018641 |
| `mining` | +hard mining | **43.286** | **+0.659** | 0.7713 | 0 | — | — |
| `full` | 三项全开 | 33.036 | **−9.591** | 2.1055 | **32** | 0.030007 | 0.002900 |
| **`hc_cal`** | +**0.006**·L_hc（修复后） | 42.512 | **−0.115** | **0.7264** | 0 | 0.005468 | **0.013639** |

**读法**：三项单独 Δ 之和 = −10.11，合成 `full` 实测 −9.59（近似可加）；9-LUT 的 −9.59 与全 75 的 −9.20 一致。**L_hc 一项解释了 full 臂的全部回退。**

**怎么归因的（D2 主因：单位失配）**——对模型输出 f 的批梯度范数（`analysis/lhc_grad_probe.json`）：

| 状态 | ‖∇L_rec‖ p50 | ‖∇(10·L_hc)‖ p50 | **比值** |
|---|---:|---:|---:|
| GLUT 原版 init（f=2x） | 0.01275 | 11.080 | **869×** |
| rec 臂收敛态 | 0.01804 | 4.130 | **229×** |

**Adam 逐参数用 `g/√v` 归一化，两项相加时 L_rec 的贡献在数值上被完全淹没。** 训练轨迹的直接证据就是上表 `rec` vs `hc` 的 L_rec/L_hc 反转 ⇒ **`hc` 臂优化的实际目标是「只对齐 hue」**，与 `viz/failure_fullarm_*.png` 吻合（预测图色相方向对、明度/彩度整体偏离）。

**校准后的 λ**：要让 `10·L_hc` 退回扰动量级（≈L_rec 的 10%），λ 需为 **0.00437**（论文公式口径）/ **0.00544**（chroma 下限口径）——**比论文的 10 小三个数量级**；实际取用 **0.006**。

**次因 D1：L_hc 的 chroma 奇点**。`cos_h = (a_p a_g + b_p b_g)/(C_p C_g)`，解析梯度 `|∂L/∂(a_p,b_p)| = C_g·sin(Δh)/C_p`，在预测彩度 `C_p → 0` 处发散。批梯度 max/p50：GLUT init **165.0** → rec 收敛态 **5.19** → 加 chroma 下限后 **1.61**。

**附带发现 D3/D4（结论与直觉相反）**：`torch.clamp` 反向只在闭区间内传梯度 ⇒ opacity 的 raw 参数一旦越过 1.0 就**永久冻结**（单向陷门）。实测 `rec` 臂 step 1 就有 62.5% 越界、step 400 有 87.5%；加了 `R_sparse` 后 **step 1 就 100% 越界**，且 `∂R_sparse/∂o` 在 o=1 处是 **−14.8（推高）**。⇒ **任务卡怀疑的「R_sparse 把 opacity 推向 0 → 原语塌缩」不成立，方向相反**；`alive_frac` 低于 1 的成因是高斯在权重归一化里被邻居挤掉，不是 opacity 归零（`opacity_frac_below_0.05` 恒为 0）。

**结论**（`REPORT.md:297-303`）：
- `runs/full` 的全部数字（32.72 dB / ΔE00 2.06）**作废，不得用作 RD 臂基线**；
- **L_hc 默认不用**（论文自述总增益 +0.11 dB，我方修复后实测 −0.12 dB）；
- **「要用就必须同时上 chroma 下限 + 梯度校准的 λ，两者缺一不可」**；
- λ_hc 的单位口径**无法核实**（GLUT 仓库空壳），三种同样合理的还原本轮**不猜**；
- **主实现一行未动**（`model.py`/`losses.py`/`train_a0.py`/`run_a0.py` 保持原样）。

> **这个 bug 直接解释了 RD-G 为什么「没有任何感知/色相损失」**（`RDG.../REPORT.md:64`：「A0 实测 `10*L_hc` = −10.73 dB（量纲错），本轮不碰」），也直接产出了下一轮协议 §9.2 的硬性要求：**Lab/chroma 必须先归一化到无量纲，不得重演旧 A0 的约 229 倍梯度放大；训练日志单独记 `grad_norm(L_func)` 与 `grad_norm(10·L_hc)` 的比**。

## 5. 颜色崩塌的证据（MCQ-L）

**实验目录**：`experiments/MCQ_full_local_l1l6_20260804/`（dense 档）、`experiments/MCQ_basis_where_l1l6_20260804/`（basis 档）

### 5.1 ⚠ 这个 `var_ratio` 与 RD-G 的 `var_ratio` 不是同一个量

| | RD-G 的 `var_ratio` | **MCQ 的 `var_ratio`** |
|---|---|---|
| 定义 | 预测输出色在**样本间**的方差 / 目标输出色在样本间的方差（同一组固定色上算） | **每张图的编辑增量的空间方差之比**：`mean_i Var(pred_i − source_i) / mean_i Var(target_i − source_i)` |
| 塌陷成什么时候 → 0 | 所有图都吐**同一张平均 LUT** | 模型**几乎不改颜色**（输出 ≈ 输入） |
| 出处 | `experiments/RDG_transformer_20260803/config/train_rdg.py:157-162` | `experiments/MCQ_full_local_l1l6_20260804/train.py:236`，逐样本量在 `:336-337` |
| 收敛后典型值 | G-Base **0.967** | config_a **0.317** |

**所以 0.967 与 0.317 不能并排讲**。RD-G 的 0.967 说的是「不同图确实给出不同 LUT」；MCQ 的 0.317 说的是「给出的编辑幅度只有 GT 的三成」。**颜色崩塌指的是后者。**

### 5.2 门槛与选择规则

`selection_score`（越低越好，`train.py:256-270`）：
```
score = de00_p50 + 0.25·de00_p90 + 50·outside_leakage_p50
      − 0.01·(psnr_in + psnr_boundary + psnr_out) − 0.25·auc_cgt_p50
      − 0.05·delta_const_db − 0.05·delta_shuffle_db
if var_ratio < 0.05:  score += 100          ← 方差比死刑（train.py:265-266）
for k in (delta_const_db, delta_shuffle_db):
    if k < 3.0: score += 10·(3.0 − k)       ← 3 dB 因果门（train.py:267-269）
```
- **`var_ratio < 0.05` 是硬惩罚（+100）**，不是「≥0.6 才算好」——**MCQ 这条线上没有 0.6 那种门**，所有臂都远在 0.05 之上，**死刑没触发，但离 1.0 差 3 倍以上**。
- **3 dB 的因果门（`delta_const` / `delta_shuffle`）所有臂全部未过**：最好的 config_a 只有 `delta_shuffle = 1.901 dB`（`runs/config_a/metrics.json :: final.select.delta_shuffle_db_p50`）。项目自己的说法是「只能说 A 的 instruction 响应更强，**不能据此宣称已经充分听懂指令颜色**」（`AB_VISUALIZATION.md:29`）。

### 6.3 Gaussian-aligned visual pooling（`P:395-412`）——「谁池化谁、对齐到什么」

```
a_i(p) = m_pred(p) · N( I_in(p) ; mu_i, Sigma_i )
v_i    = Σ_p a_i(p) · [ RGB(p), Lab(p), V(F_pre(p)) ] / ( Σ_p a_i(p) + eps )    # V: 1024 → 256
```

| 项 | 值 |
|---|---|
| **对齐到什么** | 对齐到**每个 Gaussian 自己在 RGB 颜色空间的支持域**（`N(I_in; mu_i, Σ_i)`），并被 Where 的空间场 `m_pred` 掩蔽 |
| 池化输入通道 | `RGB(3) + Lab(3) + V(F_pre)(256)`；再拼 `log(Σ a_i)` 与 valid bit |
| 输出形状 | **48 × (3+3+256+2) = 48 × 264** |
| 空像素兜底 | 无有效像素时回退 **masked global pool**，**不产生 NaN** |
| 在哪个网格上做 | 池化在 **F_pre 网格 (H/16 × W/16)** 上，`m_pred` 用低分辨率 readout；loss 的 natural 采色仍在全分辨率用 guided-upsample 的 `m_hi`（实现侧，`q3vl/what/config.py:132-142`） |
| 这一步保住的五样东西 | `M_color` token 级语义细节 / `z_style` 全局风格 / `F_pre` 局部视觉内容 / Where 的显式 ROI 约束 / **每个 Gaussian 对应的真实颜色分布** |

### 6.4 Shared Transformer backend（`P:414-435`）——**「shared」有两层含义，别混**

1. **两个 generator 共用同一「容量等级」的 48-slot Transformer**（同深同宽同 query 数），目的是把差异归因到「完整生成 vs 共享 geometry」，**而不是小 MLP 容量差**（`P:416, :470`）。⚠ **不是跨臂共享同一份权重**——每臂独立训练。
2. **SB48 内部的 shared**：48 个 `mu_i, Σ_i` 是**跨样本共享**的可训练量（`P:461`）。

```
48 learned slot embeddings + WC tokens
  ─▶ 2 个 seed Transformer block
  ─▶ provisional / fixed Gaussian geometry
  ─▶ Gaussian-aligned pooling v_i          ← 梯度可穿过 pooling 回到 geometry
  ─▶ 4 个 refinement Transformer block
  ─▶ 48 个独立 decoder head + 1 个 global head
```

| 项 | 值 | 出处 |
|---|---|---|
| **每 block 规格** | **宽 512、8 heads、FFN 2048、pre-norm** | `P:427` |
| **总层数** | **2 + 4 = 6** | `P:422-424` |
| slot 数 | **48** | `P:419` |
| 每个 block 内做的五件事 | ①48 slots 间 self-attention（建模 Gaussian 之间的互补与竞争）②cross-attend **完整 `M_color`**（避免所有语义被压进单个向量）③接收投影后的 `v_i` 与 WC tokens ④`z_style` 生成的 **ModLN** 调制 ⑤**zero-init gated residual**（防训练初期视觉或 Where 分支压倒颜色语义） | `P:429-433` |
| decoder head | 输入 `[h_i, P(z_style)]`；**不存在 LUT-ID embedding，也不存在「小 MLP 从 pooled feature 直吐 1000+ 参数」的路径**。head = Linear→GELU→Linear，**第二个 Linear 零初始化** | `P:435`；`q3vl/what/config.py:168-176` |

### 6.8 What Loss 定档（`P:573-583`）

```
L_what = 1.00  L_func
       + 10.00 L_hc
       + 0.001 R_sparse
       + 0.05  L_style_cos
       + 0.05  L_style_dist
       + 0.02  (L_var + L_cov)
       + 0.10  L_bake
```

| 项 | 权重 | 定义 | 依据 |
|---|---:|---|---|
| `L_func` | **1.00** | `Charbonnier(T_pred(x) − T_gt(x))`，每样本 **2048** 个 RGB 查询点：1024 固定分层 uniform-RGB + 1024 来自当前 `I_in` 的 natural RGB（local 按冻结 `m_pred` 加权）。**uniform/natural 各占 50% 且分别报告** | 把 GLUT/CGLUT 的 RGB 重建改为**更直接的 LUT function 监督**；**GT 是 `T_gt(x)`，不是 `I_tar`** |
| `L_hc` | **10.00** | CIELab hue cosine，GT chroma 加权 | 沿用 GLUT/CGLUT 公开权重方向，**但 Lab/chroma 必须先归一化到无量纲，不得重演旧 A0 的约 229 倍梯度放大**；训练日志单独记 `grad_norm(L_func)` 与 `grad_norm(10·L_hc)` 的比（**见 §4.3，这是 A0 的 bug 直接写进协议**） |
| `R_sparse` | **0.001** | opacity/existence 的 binary entropy | GLUT/CGLUT 公开权重 |
| `L_style_cos` | **0.05** | `1 − cos(z_style, z_gt)` | style-code **只防坍缩**，不承担 LUT 重建主任务 |
| `L_style_dist` | **0.05** | `Huber(d_style(i,j), d_func(T_i,T_j))`，batch 内成对距离。**amendment A-2 定档**：`d_func = ‖u(T_i) − u(T_j)‖₂ / C`，`u` 是**未经 SRHT、未经 L2 归一化**的 `flatten(T(x)−x)`，`C` 是**在 train LUT 集上预计算的固定整体常量**，**禁止逐 batch/逐图归一化**（与 s 轴同类纪律） | 理由：`z_gt` 丢掉 `u` 的**幅度**，会让「同一 look 的强度变体」目标距离为 0；本仓库语料是 Lightroom preset，强度变体常见 ⇒ 否则 `L_what` 里**没有任何一项监督 `z_style` 的编辑幅度** |
| `L_var + L_cov` | **0.02** | `L_var = mean max(0, 1 − std(z_style_dim))`；`L_cov` = 归一化平方非对角协方差 | 用跨卡 all-gather 后的 batch 统计；单卡时用 **stop-gradient FIFO statistics queue** |
| **`L_bake`** | **0.10** | `Charbonnier( T_tetra(bake_33(T_pred), x) − T_pred(x) )`——**每次训练前向都在 33³ lattice 烘焙、用生产四面体插值回读同一批查询点** | 「保证训练出来的函数**在交付形态下仍成立**，而不是只保证解析 renderer 好看」 |

**纪律条款**：「该配方是**所有 12 个 What 臂的统一起点和主配置**，不为单个 arm 单独调权重。只允许在 preflight 阶段修复单位、非有限值或实现错误；**不得根据主实验结果事后改 loss 再只重跑失败臂**」（`P:585`）。
**「`I_tar` 不进入 `L_what`」**——最终渲染图在评测时由预测 mask 与预测 LUT 显式合成再与 `I_tar` 比较，**这样能把 Where 误差、LUT function 误差、最终成像误差分开归因**（`P:587`）。

**明确不采用的 loss**（`P:72-78`）：MetaCanvas 的 flow-matching（任务域不同，只迁移结构与冻结边界）｜语言 causal-SFT loss 训 connector（SFT 已在上游独立完成）｜direct-grid LUT 的 TV/monotonicity（会压低局部颜色变换容量）｜CIEDE2000 当高权重反向主损失（只用于 checkpoint 选择与报告）｜离散 LUT 分类损失（`z_style` 是**连续函数码**，不是 LUT ID）。

### 6.9 判据（预注册数字）

**bake gate（硬数字，`P:695-700`）**：
```
analytic vs 33³ tetrahedral readback:
  mean RGB MAE ≤ 1e-4
  p99 RGB error ≤ 5e-4
  non-finite = 0
```

**Where gate（选冻结 Where checkpoint 用，`P:323-335`）**：

| 指标 | 门 |
|---|---:|

**What 的选择规则（字典序，只在 `V_what` 上选，`P:721-732`）**：
1. 先满足 **bake gate + finite gate + instruction-shuffle 正向依赖**；
2. 主排序：**local 最终图像 median CIEDE2000**；
3. 次排序：**LUT function CIEDE2000 p90**；
4. 再看 boundary-band CIEDE2000、参数量、延迟。
**最终 top-2 必须是两个不同配置**，不能是同一 arm 的相邻两步；**只在所有选择冻结后打开 `T_final` 一次**；主差异用 **paired bootstrap 95% CI**；必须报 **WC × generator 的 interaction**；`T_lut_unseen` **单列**。
（A-4 补充：`main_board` 增加 context 维度，**默认 generated**；teacher-context 榜并列报告。）

**成立门槛（汇报结尾用的一句，`P:823`）**：
> 只有在 **Where gate、What 负控制、unseen-LUT split 和 33³ bake gate 同时成立**时，才能把结果写成完整方法贡献。否则应按失败所在阶段分别报告，**不能用最终平均图像指标掩盖 Where 坍缩、style collapse 或 LUT 泄漏**。
