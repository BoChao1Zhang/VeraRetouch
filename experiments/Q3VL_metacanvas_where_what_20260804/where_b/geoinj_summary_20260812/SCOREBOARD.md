## 要验证的结论

十一个已落盘但未读的臂里，哪些结论真的被数字支持：如果这张板成立，我们就能说
**「续训仍在爬（0.7909），P2 结构损失包是零效果而非负效果，SHAPE3 至今无法裁决」**；
失败就不能说这三条里的任何一条，得回去补测。

## 为什么需要验证它

几何注入臂的 Δ 必须对**最新**基线算（HANDOFF §3.4）。基线读错，M1 门的
+0.008/+0.015 就全部错位；而 S14「P2 费 IoU」和 SHAPE3 的层-3 裁决都写进了
WHERE_STATE，审稿人会直接引用这两条。

## 怎么验的

## 3. 判读与三条更正

### 3.1 新基线 = 0.79095，注入臂的 Δ 全部改对它算

CONT2 落在 **0.79095**（+0.0140 over CONT，p=1e-4），且**曲线仍未平**：两次续训都是
撞 `max_hours` 停的（2541/4000、3753/6000），在线 quick-eval 到最后一档还在涨
（…0.8107 → **0.8273**@step3500 → 0.8159）。

⚠️ **主榜数字来自 step3500 的 checkpoint，不是 3753 的 final**
（`.checkpoint_selection.selected == 3500`）。今天提交的三个 PCH 臂因此一律 resume
`amort_step3500.pt`——这样 **M0 恰好就是 0.79095 这块板本身**。

**对 S13 的影响**：0.79095 已越过 U_replay 的几何族上界 0.7596，正在逼近全体 0.8040。
「模型已打到信息论天花板」这句话现在**由续训本身部分证伪**——天花板还没到，
而且**不是靠注入涨的**。注入臂必须在 0.79095 之上再要 +0.015 才算晋级。

### 3.2 更正 S14：P2 结构损失包是**零效果**，不是「费 IoU」

WHERE_STATE §二 S8/S14 写「三臂 0.7477–0.7522 **全部低于 0.7622 基线 ⇒ 费 IoU，不采纳**」。
这个比较是**步数不匹配**的：四个 P2 臂是从 P3'(1200) 再训 **500 步**，而 0.7622 是从同一
起点训 **2541 步**的 CONT。拿 500 步的臂比 2541 步的臂，正是项目自己的 U4 步数匹配纪律
禁止的比法。

**对它们各自的同起点基线 P3'(1200)=0.74172 重算，四臂全部落在 p=0.34–0.59 的零效果带**
（+0.0014 / +0.0011 / −0.0020 / −0.0013）。

⇒ **结论方向不变（不进配方），但理由要改**：不是「结构损失费 IoU」，而是
**「结构损失在这个权重族里什么也没买到，而同样的算力用于续训能买到 +0.02」**。
按现有措辞，审稿人问「你们怎么证明是损失有害而不是训练不足」时无法回答。
建议 WHERE_STATE S8/S14 按此改写。

补充：HANDOFF §2.1 只列了三个 P2 数字（0.7522/0.7486/0.7477），**漏掉了 p2struct_hi 的
0.74945**；盘面上是四个臂（{p2struct,p2w}×{base,_hi}），没有 A2/W2 目录。

### 3.3 SHAPE3 至今**无法裁决**——预注册判据从未被计算

SHAPE3 的预注册判据是 `shape_residual`（HANDOFF §3.3）。全仓 `rg shape_residual`
只有三处命中：`q3vl/whereb/edgequal.py:32` 的导出、`:311` 的定义、以及 HANDOFF 里的散文。
**没有任何调用点**；`/home/bc/data/runs/` 与 `experiments/` 下的产物文件里该字符串命中数为 0。

⇒ 两个 SHAPE3 臂只按 IoU 判了，而 IoU 恰恰是该臂**明确说了不要只看**的列。
按 IoU：A（eikonal）0.73467 **低于**自己的基线（−0.0040，p=0.029）且低于同容量对照 B
（−0.0057，p=0.016）；bF1 上 A 与 B 无差别（+0.0005，p=0.90）。
**「A 的形状残差显著低于 B」这一条既没被证实也没被证伪。** 要裁决必须补跑一次
带 `shape_residual` 的评测（需 GPU 前向，非纯 CPU）。
次要：SHAPE3_B 的 `.arm` 记成了 `"P3prime"` 而非 `"SHAPE3"`。

## 4. 两个会静默算错 Δ 的坑（后续做板的人必看）

1. **`.baselines.center_prior` (0.51702) 与 `.baselines.random_floor` (0.25824) 是
   pooled 全 400 的值**，尽管它们所在的块标着 `"convention": "matched-area top-k IoU"`。
   normal-only 的基线只在 `.contexts.<ctx>.headline_normal_only.*` 里。
   顶层取基线 + 嵌套块取 headline ⇒ **每个 Δ 少算约 0.031**。
2. **HANDOFF §3.6 的 W01 参照值（generated 0.4874 / gt 0.5109）不在 W01 的产物文件里，
   但它们有出处**（主 agent 2026-08-12 裁定，本条按裁定改写）：

   出处链 = **U7 裁定后的 normal-only 重算值**，由前任 agent 的重算管线在 W01 的
   per-sample 上重跑得到，**不是** W01 原始 `metrics.json` 里的任何键。该管线的可信度有
   独立佐证：它曾**逐位复现 pooled 0.5088**。
   ⇒ **数字保留、照常引用**，但引用时必须写明「U7 重算值，非 W01 原始产物」，
   否则下一个人会像我一样去 W01 的 metrics 里找、找不到、然后误判成编造。

   W01 原始产物里能直接读到的是
   `.strata.generated.winner_confidence.normal.grid_hard_iou = 0.53349`（**n=515**，
   另一块板、另一口径，**不可**与 amort 的 V_where local n=224 直接相比）。
   另：中心先验 HANDOFF 写 0.4853，本板实测 0.48565（四舍五入 0.4857），差 0.0004，
   同属重算口径差，不影响任何判读。

`amort_P3prime_20260810` / `amort_P1_20260810` 的 `.checkpoint_selection` 记着
`step1200.pt missing`、`selected` 缺失——headline 照样落了盘，但**产出它的权重是哪一份没有记录**。
