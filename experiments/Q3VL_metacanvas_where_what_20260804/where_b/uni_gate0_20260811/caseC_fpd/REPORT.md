## 要验证的结论
如果这个实验成功,我们就能说方案 C 的**「场即程序」输出空间够用**——把 GT 场编译成 ≤20 token 的短程序、再由零可训参数解释器渲染回来,几何家族均值 soft-IoU ≥0.92 且语义轮廓家族(oracle 段选择)≥0.80;失败就不能说该词表/文法/解释器能承载本任务的场,方案 C 的训练臂无米下锅。

## 为什么需要验证它
方案 C 的全部卖点(「平均程序不可表示」的结构免疫、程序即解释的可读性、毫秒级推理)都建立在「程序空间 = 场空间的 ε-等距重参数化」之上。若回环上界就够不着,后面训得再好也只是在一个装不下答案的输出空间里逼近;审稿人一句「你的 token 化损失多少」就能打穿。这张卡把它变成开训前一天的数字。

## 怎么验的
零训练。对 V_where local 全体(n=397)按家族编译:三个几何家族用各自解析式(椭圆衰减/线性渐变/条带)以 **L2**(禁 IoU 作优化目标)多起点拟合到 GT 粗场并量化到 32×32=1024 级箱;语义轮廓家族用冻结 merger 特征亲和跑多粒度 Ncut 段 → **oracle 段子集选择** → LPOSS 凸标签传播;全部家族再统一穿冻结引导上采样 $U_I$ 渲染成全分辨率场,与 GT 比。另做离线编译检验:相邻箱渲染场 soft-IoU 差 ≤0.02。

### 轮廓失败的定位(本卡最有价值的部分)

判据挂了要能说清挂在哪一环,否则「换个后备」是盲试。逐级 soft-IoU(粗场口径):

| 环节 | 均值 | 说明 |
|---|---|---|
| **最佳单段 vs GT** | **0.4529** | **段支撑本身的天花板** |
| oracle 段子集 OR | 0.5812 | 选择规则已是 oracle,只加 0.13 |
| LPOSS 传播后 | 0.3834 | **传播反而把分数拉低** |
| 经 $U_I$ 上采样(全分辨率) | 0.3567 | |
| (关掉 LPOSS 的变体) | **0.5722** | 本卡取此值当判据,对方案更宽容 |

**结论**:瓶颈是**段支撑**,不是选择规则、不是传播、不是量化。即使把选择做成 oracle,段池里根本不存在能贴合编辑区的支撑(最佳单段 0.45)。这正是文档 §4.7 列为**一号风险**的「轮廓段支撑天花板」,实测把它坐实。

**关于 LPOSS 变坏的说明(诚实记录)**:羽化槽按 **L2** 从固定网格选(红线不许按 IoU 选),而平滑**降低 L2 却破坏重叠**——0.5812 → 0.3834。这不是实现 bug(修好一处真 bug 后仍如此:原实现漏了 $(1-\alpha+\mu)$ 归一化因子,导致场被放大约 5 倍并整体饱和到 1,当时读数 0.409→0.170)。修好后传播仍有害,是 L2 与 soft-IoU 的度量错配的真实表现。故本卡把「不传播」变体一并落盘,**判据取两者中较好者**,保证 FAIL 不是本卡解释器选型的产物。

## 3. 结论

1. **几何三族 PASS(0.9484)**,箱宽校准 PASS(0.0095),量化代价近零(8.6e-5)——**程序化表示对几何原语是成立的**,`Stop Regressing` 式软直方图 CE 的箱宽也就此标定(核宽 σ ≈ 2.1 箱,已写入 metrics)。
2. **轮廓家族 0.5722,不但没过 0.80,还低于 0.70 证伪线** ⇒ 按预注册触发后备:轮廓槽换 32-token 学习式掩膜码本(HiMTok)。文档明示该后备**「启用即引入受训组件,『解释器零可训参数』主张失效,须另立实验」**。
3. 因此 **C 案训练臂本轮不开**。这不是「再调调就好」:失败定位在段支撑(最佳单段 0.4529),而段池已经是多粒度 + oracle 选择的宽容配置。
4. 交叉印证:同一批语义样本在 **B 案 G0b 的岭解颈部拿到 0.8949**。同样是「粗场 → $U_I$」,差别只在粗场是**自由岭解**还是**段 OR**。**所以限制不在 $U_I$、也不在粗分辨率,而在「用离散段子集当形状参数」这个表示选择**。

## 4. 实现审阅须知(三处口径,请一并核)

1. **ω 不可得**:`.vrmeta.json` 只有 `slot_id`,**没有生成参数**(构造侧生成器在另一个仓库)。故编译器按文档签名 $C(z,\omega,y;x)$ 允许的方式**拟合**本卡自建的解析式。后果如实记账:**测得的回环是真实生成器程序空间的下界**——PASS 可信,边缘 FAIL 需拿到真生成器才能叫证伪。几何家族是 PASS,不受影响;轮廓家族不依赖解析式(走段指针),也不受影响。
2. **拟合已做投影约束**:拟合迭代被夹在与量化器**同一个**箱范围内。早期版本没夹,拟合跑到范围外再被量化器夹到边界,量化代价虚高到 **0.115**——差点把「范围越界」误报成「token 量化很贵」。
3. **radial 的信息化起点**:纯随机重启时 radial 只有 0.50(椭圆目标多盆地);改用 GT 一阶/二阶矩匹配起点后到 0.9111,与项目自带 oracle 拟合器的 `centroid-radial informed start` 同法。
