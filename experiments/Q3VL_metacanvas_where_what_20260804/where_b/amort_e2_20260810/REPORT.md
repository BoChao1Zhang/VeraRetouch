## 要验证的结论

如果这个实验成功,我们就能说 **W01/W02 的塌缩是「回归目标本身是个坏目标」(M2),而修复只需要
在 oracle 脚本里加一个正则项** —— 这是整个诊断包里唯一可能翻案、且成本只有 5% 的一条;
失败就不能说这句话,反过来说明**病态是 oracle 0.97 天花板的代价本身**,M2 这条修复路线关闭。

## 为什么需要验证它

E1 把 M2 抬成主嫌:有效条件数中位 8.4e5、Spearman(cond, oracle IoU) = −0.52、18 次重启只有 1 次
进最优盆地。若 Tikhonov 重算后 oracle 仍保住 0.97 而目标变光滑,那么**新架构根本不用设计**
(RESEARCH 附录 A:「跳过 5% 成本修复直上 100% 成本新架构」正是不做的代价)。

## 怎么验的

**第 0 项(零成本前置)**:核对 `w_dir` 符号规范化在 oracle 写入侧与训练读取侧是否逐字一致 ——
若不一致,回归目标里混着人为双峰,足以独立解释塌缩。全量普查 train 75,544 + V_where 400,
两个 readout。

**主体**:V_where 400 条,用 E1 的本地缓存重建 Phi-71,在 oracle 拟合目标里加 Tikhonov 项,
λ 按 E1 实测谱定标(目标 cond≈1e3),扫 6 档 λ,每档报**重算后 oracle 解码 IoU**(验收门 ≥0.95)、
**重算后有效条件数**、以及**真正要紧的那个量**——`w_eff` 的逐维跨样本变异系数 CV。

## 0. 第 0 项结果:**符号规范化一致,不是病因**(阴性,但排除了一个)

| 检查 | train / band | train / cband12 | V_where / band |
|---|---|---|---|
| 有 ok 拟合的样本 | 75,544 | 75,543 | 400 |
| 落盘 `canonical` 标志为真 | 75,544 | 75,543 | 400 |
| 落盘 `w_dir` 满足符号规则 | 75,544 | 75,543 | 400 |
| **训练侧 `w_dir_of(w_raw)` 满足符号规则** | **75,544** | **75,543** | **400** |
| 三者全部一致 | **100.00%** | **100.00%** | **100.00%** |
| max&#124;落盘 w_dir − 训练侧 w_dir&#124; | 5.55e-16 | 5.55e-16 | 3.33e-16 |

**机制**:`oracle.py:395` 在**序列化之前**调用 `canonicalize`,所以落盘的 `w_raw` 本身就是规范的;
训练侧 `fields.py:oracle_fields` 用 `w_dir_of(w_raw)` 重算,而 `w_dir_of` 只做**保号**归一化,
因此**按构造继承**规范符号。`oracle.py:415` 另有 `canonicalisation_changed_loss` 拒收兜底。

**结论:E1 NOTES §三.A 的隐患不成立,回归目标里没有人为双峰。**
**⇒ 任务卡预留的「只修符号、不加 Tikhonov」对照臂不需要开**(省一个臂)。

### 0b. 但同一次普查测出了一个**新的、真实的**目标不连续源

规范化消掉了 `w → −w` 的二重简并,**代价是引入一条边界**:符号规则以「绝对值最大的系数为正」
为轴,当前两大系数接近相等时,这个轴是掷硬币。

| 读数 | train / band | train / cband12 |
|---|---|---|
| 轴间距 &#124;w&#124;₍₁₎/&#124;w&#124;₍₂₎ 中位 | 1.475 | 1.511 |
| p05 | 1.033 | 1.033 |
| 间距 <1.05 的比例 | 7.44% | 7.30% |
| 次大系数**符号相反**的比例 | 54.2% | 54.6% |
| **活跃翻转边界(间距<1.05 **且** 次大反号)** | **3.92%** | **3.77%** |
| 同上,间距<1.20 | 13.9% | 13.2% |

对这 **3.9%–13.9%** 的样本,输入的无穷小扰动会交换主轴并**翻转全部 71 维目标的符号**,
使 `L_dir = 1 − cos` 从 0 跳到 2(最大值)。这是**自造的** M2 型不连续,与 E1 测到的 Hessian
病态**互相独立**,且**修法便宜**:`L_dir` 改用符号不变形式(`1 − |cos|`),或干脆按 P1/P3 的
做法把监督搬到输出空间(mask 对翻转天然不变)。**已列入待决策。**

## 1. 主体结果:Tikhonov 重算 oracle(n=400,band)

λ₀ 定标:`λ_max` 中位 **4.0211e+04** ⇒ `λ₀ = λ_max/(2·1e3) = 2.0106e+01`(目标 cond 1e3)。

## 2. 判读

### 2.1 验收门未过 ⇒ **E2 的 GPU 重训阶段不开**

任务卡写明「先验收重算后 oracle 解码 IoU ≥0.95 再往下」。**没有任何 λ 通过。**
因此 E2 不申请 GPU 槽位、不进队列 —— 这条 5% 成本的修复路线**到此关闭**。

### 2.2 **病态不是缺陷,是 0.97 天花板的价钱**(本卡的真正结论)

IoU 与 cond 在整条扫描上是**严格单调的此消彼长**:每压低一个数量级的条件数,
就付出可观的 IoU。这说明 Phi-71 的**近零空间方向在真实地参与拟合掩膜** ——
它们不是噪声维度,而是 oracle 达到 0.9748 所必需的自由度。

**推论(直接推翻 M2 的修复前提)**:「目标病态」与「oracle 表达力 0.97」在这个基底上是
**同一件事的两面**,不能只要一面。E1 的诊断(病态为真)成立,但它蕴含的修复方案(正则化目标)
**被本卡证伪**。

### 2.3 **更要命的是:目标从未变得可回归**

`CV>1 的维度占比` 在**全部六档 λ 上都是 100%** —— 没有任何一维的跨样本均值能盖过它自己的散布。
CV 中位从 14.23 掉到 4.36 之后就**平台化甚至反弹**(4.36 → 4.37 → 4.35 → 6.90 → 5.18)。

**即使愿意付出 IoU 的代价,也换不到一个可回归的目标。** 这是本卡最强的一条:
Tikhonov 在这个问题上**两头都不讨好**。

### 2.4 与 E5 / E3 的合流

- **E5**:D(Phi-71 + guided upsample)忠实复现任意输入场(解码−先验 Δ≈0)⇒ 基底不是瓶颈;
- **E3**:两个训练好的头都被零参数中心先验解释得比被 GT 更好(corr 0.64/0.61 vs 0.47/0.53)
  ⇒ **M3 坐实**;M4 **不成立**(指令确实在条件化输出,换主体掉 0.145,但只比中心先验高 +0.033);
- **E2(本卡)**:目标的病态无法在保住天花板的前提下移除 ⇒ M2 的修复路线关闭。

**三卡合起来把「修目标 / 修 w 空间投影 / 在 w 空间迭代精修」整族处方全部关掉**,
只剩下一条活路:**改条件接线 + 直接在输出空间产生更好的场**(P1)。

## 3. 结论

1. **第 0 项阴性**:`w_dir` 符号规范化训练侧与 oracle 侧 100% 一致(n=75,544+75,543+400,
   max 偏差 5.6e-16),**不是病因**;「只修符号」对照臂**不需要开**。
2. **第 0b 项阳性(新发现)**:规范化自身引入一条翻转边界,**3.9%(间距<1.05)到 13.9%(<1.20)**
   的训练目标坐在上面,会让 `L_dir` 在无穷小输入扰动下从 0 跳到 2。修法便宜,已列待决策。
3. **主体证伪**:Tikhonov 重算 oracle 在**所有** λ 上未过 0.95 验收门;
   把 cond 压到 5.6e3 要付出 IoU 0.9748→0.4874。
4. **且目标从未变可回归**:CV>1 的维度占比在全部 λ 上恒为 100%。
5. **E2 的 GPU 重训阶段按判据不开**,不占队列。

## 4. 建议下一步

1. **M2 修复路线关闭**,不再投入;E1 建议的「基底正交化/白化」也应重新评估 ——
   本卡显示条件数与表达力在这个基底上是绑定的,单纯白化不改变张成空间,
   因此**也不会**改变这个 trade-off(白化只重排坐标,不消除近零方向的贡献)。
2. **`L_dir` 的符号不变化(或直接取消)应随 P1 一并处理**(§0b)。P1/P3 的监督本就在输出空间,
   mask 对符号翻转天然不变,这条隐患**自动消失** —— 这是本卡给 P1 增加的一条独立理由。
3. **E4(2 头 WTA)的优先级应下调**:M1 的前提在 E1 已被弱化(满秩、零近零特征值),
   本卡又证明「目标难回归」不是多模态而是**基底与天花板的结构性绑定**。
4. 判据纪律沿用:本卡无 AUC;所有 IoU 为 soft-IoU(minmax),oracle 侧口径与 Where-A 一致。
