## 要验证的结论

如果这个实验成功，我们就能说「**RO-9 的 AUC=0.648 是读出算子的问题，不是 VLM 里没有 where**——
同一批 attention 张量换一套聚合方式就能到 0.92–0.93，追平零训练 CLIP 的 0.941；
但**这四处修复只买到定位质量，买不到指令依赖**」；
失败（修完仍 <0.85）就不能说这句，只能说 GL token attention 里连"图像驱动的主体显著性"都读不干净，
RO-9 的死因是信息本身不在，而不是算子。

## 为什么需要验证它

负责人的原话是「效果差，也不应该有这么差」——RO-9 的 0.648 vs 免费 CLIP 的 0.941 是本项目
当前最尖锐的质疑（"VLM 不如免费 CLIP"）。若 0.648 只是四个算子选择造成的，那么 EXPERIMENTS_v3
里基于 0.648 做出的所有降级判定（RO-9 判死、RO-3 的解读、"H2 只在 CLIP 侧成立"）都建立在一个
被算子压低的数字上；反过来若修完仍上不去，"VLM 里没有 where"这条负面结论才算真正闭合。

## 怎么验的

在 **S-val 区域对立批 214 源（有效 212）** 上重跑 RO-9 的完整流程（生成 plan → teacher-forced
eager 前向 → 取 GL token 对 256 个 image token 的 pre-softmax attention），**但保留 head 维与全
24 层**，并同时导出 post-softmax / k-k / q-q 三份并列场与 image 段 K 矩阵；再把四处可疑
（① canonical 层段 ② head 算术平均 ③ 没做 self-self ④ D-0 空转）做成四个实验轴，
用 **5 折 source-level CV（权重只在 fit 折估、数字在 hold-out 折报）** 逐段单列增量；
另在**自家视觉塔 FastViTHD** 上原样施加 RO-1 的三个 self-self 算子（13 个臂）作为组 A。

## 四、② head 聚合：pre-softmax logit 的逐头量纲差 3 个数量级

- **实测**：单样本 24×14 个 (层,头) 的 pre-softmax logit 值域是 **[−520, +972]**，
  而 head-mean 后的 canonical 场值域只有 **[−12, +1.2]** —— 直接算术平均确实让个别巨尺度的头主导。
- **post-softmax 的行内 image 段占比中位只有 0.136**（`config/verify_env.json` V5）：
  GL token 有 **86% 的注意力质量落在非 image 位置**（sink / 文本）。
  这解释了为什么"整行 softmax 后再切 image 列"（`post` 档）反而更差——sink 吃掉了动态范围。
- **四档并排**（任务卡要求的 (a)(b)(c)(d) 四档，均为 out-of-fold）：

| 档 | 定义 | AUC（`best1` 支路） | AUC（`wsum` 支路） | AUC_target（`wsum` 支路） |
|---|---|---|---|---|
| (a) `mean` | **RO-9 原样**，14 头算术平均 | 0.8393 | 0.7241 | 0.5246 |
| (b) `zmean` | 逐头**数据集级** z-score 后平均 | 0.8115 | 0.7647 | 0.5248 |
| (c) `post/mean` | **逐头 softmax 后再平均**（量纲统一到概率） | 0.7579 | 0.6967 | 0.5071 |
| (c') `post/zmean` | 同上再 z-score | 0.7399 | 0.7000 | 0.5116 |
| (d) `aucw` | 权重 ∝ 逐头 AUC_target−0.5（带符号，fit 折估） | 0.7554 | 0.6835 | 0.5590 |
| **(d') `top3`** | **逐层 top-3 头凸组合** | **0.8686** | 0.7278 | **0.5719** |
| (d'') `top5` | 逐层 top-5 头 | 0.7448 | 0.6828 | 0.5566 |

**结论**：
- **(c) 逐头 softmax（量纲统一到概率）是最差的一档**，因为 softmax 的分母被 sink 主导；
  **审查里"量纲不同"的诊断成立，但"用 softmax 统一量纲"这个药方是错的。**
- **(b) z-score 只改善定位质量，不改善指令依赖**；
- **只有"挑头"（d/d'）能把 AUC_target 推离 0.5**（+0.047 / +0.032，p ≤ 1e-3），
  并且是本实验里**唯一**让 Δ_shuffle 从 0 变成统计显著为正的一步。
  这与 RO-9 REPORT §五.2 交办 RO-3 的预期一致：**head-mean 把单头信号平均掉了。**
- ⚑ **D-31**：AUC_target 0.5719 的 CI 下界 0.524 只是**刚刚**越过 0.5，
  **这是"未触发死刑 + 一条弱正面证据"，不是"RO-9 被救回"**。

## 五、③ self-self —— 本实验最有价值的**负面**结论

### 5.1 组 A：在 VeraRetouch 自己的视觉塔上做 self-self（**回答"where 在不在 VLM 里"**）

**架构核实（一手，Apple `ml-fastvlm` 源码 + 本机实测 `config/verify_env.json` V1–V3）**：
FastViTHD = `layers=[2,12,24,4,2]`、`embed_dims=[96,192,384,768,1536]`、
`token_mixers=("repmixer","repmixer","repmixer","attention","attention")`
⇒ **只有 stage 3（`network[7]`，4 块，输入 (1,768,32,32)，24 头）与 stage 4（`network[10]`，
2 块，输入 (1,1536,**16×16**)，48 头，head_dim 32）有 self-attention**；

**四条读数（本节是本实验最该被引用的部分）：**

1. **"where 在 VLM 里"—— 有正面证据，而且不需要任何手术。**
   未改造的 VeraRetouch 视觉塔在 `emb` 读出点上 AUC **0.7297**、
   与无关对照词 `calculator`（0.5767）的配对差 **+0.120（p<1e-3）**、
   **AUC_target 0.6576** —— 这个 AUC_target **显著高于** RO-9 的 0.504、
   高于 `X_deictic` 零指令基线的 0.523，量级接近 RO-1 的 0.736。
   ⇒ **词条件的区域信息在进 LLM 之前就存在**（与 RO-2 的"emb 是唯一词特异读出点、
   LLM 逐层把它抹掉"互为独立佐证）。**where 在 VLM 里，只是在视觉塔里而不在语言模型里。**
2. **RO-1 的 +0.72 完全不迁移，最好只值 +0.010**（kk +0.0084, p=0.016；naclip +0.0103, p=0.039）。
   这不是实现问题：`VisionSurgery` 的 no-op 与复刻都做到**逐元素 0 误差**。
3. **机制解释（可写进论文）**：SCLIP/NACLIP/ClearCLIP 治的病是
   **"ViT-CLIP 末层的 attention 为了把信息汇进 cls token 而牺牲空间局部性"**——
   这个病的前提是**有一个 cls token**。**FastViTHD 没有 cls token**（一手核实），
   它的末层 attention 从未被优化成"汇聚到某一个 token"，**没有这个病，自然也没有这个药**。
   这也解释了为什么 vanilla FastViTHD 是 **0.730**，而 vanilla CLIP 是 **0.214**（系统性反相关）。
4. **ClearCLIP 的"丢残差丢 FFN"在混合架构上是毁灭性的**：单独把它拿出来（`dropres`）
   就把 AUC 打到 **0.390**（比 vanilla 低 0.32，p<1e-3）。原因也清楚：FastViT 的 block 输出后面还接
   `conv_exp`（depthwise conv + SE）与 `mm_projector`，它们是在**带残差的特征分布**上训练的；
   CLIP 那边末层之后只有一个 `ln_post` + 线性投影，对分布漂移宽容得多。

| 档 | 定义 | AUC | AUC_target |
|---|---|---|---|
| **D-0 关** | 不做 outlier 剔除 | 0.6571 | 0.5109 |

- `sink`（把跨全部层/头平均的 post-softmax 权重的高值格当 outlier 剔除）：**−0.017 ~ −0.026**，负收益。
- **`aff`（self-self 亲和度传播）是唯一有效的后处理**：受限档 **+0.0259（p=1.9e-4）**，

- **官方 A3（test-time registers）在 FastViTHD 上不可移植**（NOTES §三 U3）：官方方法要往 token

  这是**架构级的不可移植性**，不是"没做"。
- **guided filter（D-3）本轮未测**：RO-1 已实测其在全图 AUC 口径下的收益 ≤+0.002（噪声级），
  且 D-3 的正式判据是**边界 PSNR**，需渲染器就位；本轮无渲染器，**如实登记为未检验**。

## 九、结论

1. **①层 = 定位质量的主要瓶颈，值 +0.179。** canonical L8–15 的**未归一化算术平均**把
   0.816（带内最好层 L11）压到 0.661；实测最优层是段外的 L22（0.839）。
   **"0.648 是算子问题"得到正面证据。**
2. **②头 = 指令依赖的唯一杠杆，但杠杆很短。** 逐层 top-3 头凸组合把 AUC_target 从 0.508 抬到
   **0.5719**（CI 下界 0.524 > 0.5），Δ_shuffle 从 −0.0004(p=0.44) 抬到 **+0.0220(p=5.7e-4)**。
   这是 RO-9 全 24 层从未做到的，但幅度只有 RO-1 的 1/10。
   **另注意：审查怀疑的"量纲"确实存在（逐头 logit [−520,+972] vs head-mean [−12,+1.2]），
   但"用逐头 softmax 统一量纲"这个药方是错的（最差的一档），因为 sink 吃掉了分母。**
3. **③self-self：组 A 被证否，组 B 只在受限档值 +0.026。**
   **机制上说得通：FastViTHD 没有 cls token，没有 SCLIP/NACLIP/ClearCLIP 要治的病；
   ClearCLIP 的"丢残差丢 FFN"在混合架构上是毁灭性的（−0.32）。**
4. **④后处理：D-0 只值 +0.0036（outlier 占比 3.4%，本模型没有 CLIP 那种强高范数伪影）；
   官方 A3 在混合架构上不可移植；`aff`（K 自相似传播）值 +0.026，但与好的层聚合重叠。**
5. **"VLM 不如免费 CLIP"这个质疑，在定位质量这条轴上解除**（0.920 / 0.935 vs 0.941，CI 接近重叠），
   **在可控性这条轴上不解除**（0.504 / 0.385 / 0.572 vs 0.736）。
6. **where 在 VLM 里 —— 在视觉塔里。** 未改造的自家视觉塔 `emb` 读出 AUC 0.730、
   与无关词的配对差 +0.120（p<1e-3）、**AUC_target 0.658**（> `X_deictic` 的 0.523，接近 RO-1 的 0.736）。
   与 RO-2 的"词特异性在 mm_projector 输出存在、被 LLM 逐层抹掉"合起来，
   **两条独立证据指向同一个机制陈述：where 在进 LLM 前就有，是 LLM 把它抹成了指令无关的显著性先验。**
7. **RO-9 的判死不被推翻。** 死因从"读不准"精确到"读得非常准但与指令无关"。

## 十一、局限（供结果审阅 agent 核）

- **批量生成不是逐 token 复刻**（§1.1）：25.5% 的样本 plan 完全相同（那些样本上场逐比特相同，
  ρ=1.000000），其余 ρ 中位 0.927（p10 0.749）；对判据的净影响 +0.0145 AUC，**已量化但未消除**。
- **`linfit` 的 0.9349 用了 GT 掩膜拟合 24 个参数**（out-of-fold，无泄漏），
  **与 RO-1 的零训练 0.941 不是同一口径**；主叙事请用受限档的 **0.9200**（仍用了 fit 折的离散选择）。
- **AUC_target 的 `¬M` 侧受限于 prompt 可定位性**（RO-1 §6.2 登记的同一个坑）；
  主判据取 background 子集（n=165），spatial 47 源只并列报。
- **组 A 的读出点是 `emb` logit lens，不是 CLIP 余弦**（本项目视觉塔无可对齐文本塔，NOTES §一 W6 / §2.3）。
  **组 A 的绝对 AUC 与 RO-1 的绝对 AUC 不可直接横比**，可比的是同一读出点内的配对增量与无关词对照。
- **官方 A3（test-time registers）未做**（架构不可移植，NOTES §三 U3）；
  **guided filter（D-3）未测**（无渲染器，正式判据是边界 PSNR）。
- **未测下游收益**：本轮只测"s 落在哪、跟不跟指令"，没测"s 当渲染条件时的 PSNR/ΔE00"。
- **贪心瀑布不是全局最优**：每段只在前一段胜者上继续。所有被评估过的组合见
  `metrics.json.config_table` 与 `metrics_supp_restricted.json.table`，结果审阅可自行核。
- **组 A / 组 B 的臂选择是预注册的 13 + 4 个，不是穷举**；`aff` 的传播只做了 1 步、无温度超参搜索。
