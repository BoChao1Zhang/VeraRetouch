## 要验证的结论

如果 RO-3 成功，我们就能说「冻结 VLM 的**某些单个 (层, 头)** 上，**instruction 文本 token → image token** 的注意力是一张**跟着指令改指区域**的空间场，零训练可读出——G1/RO-9 的 FAIL 是**读法错**（读错了 query token、且被 head-mean 抹平），不是「VLM 里没有 where」；失败就不能说这句，VLM 读出线要整体让位给 RO-1 的 CLIP 系。

## 为什么需要验证它

论文主张「VLM 负责 where、参数通路负责 how much」（H2）目前只有 G1 的一个**否定**读数（`<retouch_light>` canonical 读出 ρ_region_opp 0.884、shuffle 0.895 反超同义 0.842）；不把「读法错 vs 假设错」分开，审稿人会直接判「你们自己的实验证明 VLM 里没有 where，凭什么还搭 where 叙事」，整条读出线失去起点。

## 怎么验的

在**不预设 token / 不预设层**的前提下，对 G1 协议数据做 1708 次 eager prefill，把 **24 层 × 14 头 × 2 读法（pre-/post-softmax）× 4 个 query 池 = 2688 个候选读出**全部导出，用 G1/RO-9 的同一判据量（AUC_target、配对 ΔAUC、ρ_region_opp）逐读出扫描，并配三条独立对照（跨图打乱指令的 shuffle 批、同区域零对比度差分场、D-CONSTRUCT 自带 GT 掩膜）与 max-stat 置换零分布。

### 4.1 pre vs post：**两者都能读到，谁更强取决于判据量，都不是决定性变量**

- AUC_target 口径：**post 略优**（0.7660 vs 0.7357，+0.030）；

⇒ **「pre-softmax 绕开 sink」这条假设得到部分支持但不是关键**：真正决定成败的是 **query 池**，不是 softmax 前后。诚实地说：**本臂预设的「绕开 sink」是核心假设，实测它只值 ±0.03，而 query 池值 ±0.35。**

### 4.2 **G1/RO-9 的死因确诊：读错了 query token**

`gl` 池（= prompt 末尾追加 `<retouch_light>`，与 RO-9 读的是同一个 special token）在**全部 24 层 × 14 头**上：

- max AUC_target = **0.5542**（零分布 q95 = 0.596，**连零分布都没超过**）；
- 差分场 max AUC = **0.5839**，**FWER p = 0.982**；
- 而**同一层同一头（L11H5）**换成 instruction 文本 token 当 query：差分场 AUC = **0.9298**。

⇒ **信息就在 L11H5 这个头里，但 `<retouch_light>` 这个 query 位置读不到它。** G1 判 FAIL、RO-9 判「24/24 层全死」，都不是层选错、不是 token 选错（三 token 同源）、也不只是 head-mean 平均——**首要死因是 query 端选了 special token 而不是指令文本 token**，次要死因是 head-mean（见 §六）。

`last` 池同样近乎读不到（差分场 FWER p = 0.08 / 0.46）——这与项目红线「**VLM 干预对象 = 整段 image tokens 非 last token**」是同一现象的两面：**last token 处的信息已经被聚合掉了**。

## 六、逐头差分场（主 agent 追加①）· **head-mean 抹掉了什么**

判据量 `AUC_diff = AUC(s(reg_a) − s(reg_b), M)`；零模型 = 逐源符号翻转（`d ↔ −d`）× 2000 次，取 2688 路的 **max** 构成零分布。

| 口径 | 值 |

| **head-mean 通道**（主 agent 全量重算；`ro9_gl_attention.py:378` 在落盘前就 `raw.mean(axis=2)`） | 区域对立 **0.5129**，同区域对照 **0.5293**（更高），spatial 子类 **0.4929** → 否定 |

## 十一、结论与建议下一步

### 结论

1. **RO-3 晋级**：融合 out-of-fold AUC_target **0.830**（判据 ≥0.75），最佳层 **L11 = 中层**（判据），末两层是全场最差两层（未触发淘汰）。**属正面证据**：max-stat 置换零分布已控 2688 路多重比较（FWER p = 0.000），shuffle 前置判别在单头与融合两级都给出正的 Δ（+0.073 / +0.108）。
2. **H2 未被证伪，且现在有了 VLM 侧的直接正面证据**：L11H5 的区域对立差分场 AUC = **0.930**（SAM3）/ **0.840**（`.cgt` 主列）/ **0.922**（构造 GT），同区域零对比度对照 **0.522**，配对 p = 5e-35。
3. **G1/RO-9 的失败是「读法错」，死因已定位到两处，主次分明**：
   - **主因 = query 端读了 special token**：`gl` 池在全 336 个 (层,头) 上 max AUC_target 0.554（低于零分布 q95 0.596）、差分场 FWER p = **0.982**；同一 L11H5 换成 instruction 文本 token 立刻到 0.930。
   - **次因 = head-mean**：`ro9_gl_attention.py:378` 在落盘前 `raw.mean(axis=2)`，head-mean 通道的同一判据量只有 **0.5129**（同区域对照 0.5293 还更高）。
   - 被证伪的仍然只是**读法**。G1 的负结果本身依旧成立、依旧值得单独成 analysis 节，只是标题要从「SFT special token 的注意力是指令无关显著场」升级为「**special token 读不到、同一层的指令文本 token 读得到**」——这是更强的一个发现。
4. **「pre-softmax 绕开 sink」只值 ±0.03**：AUC_target 上 post 略优、差分场上 pre 略优，两者都能读到。**本臂预设的核心假设被降级为次要变量**，真正的变量是 query 池（±0.35）。如实登记。
5. **换 GT 结论不变但幅度要打折**：`.cgt` 主列 0.8405 vs SAM3 对照列 0.9246，差 **0.084** —— 这就是「光靠找主体能拿到的分」。两套 GT 的 16×16 IoU 中位只有 0.459，所以这不是同义复述。
6. **D-0 在本骨干上不是承重项**（scan Spearman 0.993，max 差 0.0014）——按 PLAN 的 D-0 判据可跳过。
7. **未解决**：L11H5 的逐案例分布是双峰的（多数 >0.9，少数塌到 0.5），它**不是稳定分割器**。

- **本实验只测「读得到」，没测「用起来有多少下游收益」**——`ro3-fused` arm 的价值需 RD 臂实测。
