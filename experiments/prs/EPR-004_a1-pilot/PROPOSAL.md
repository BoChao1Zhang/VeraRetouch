# EPR-004 · A1 两遍式 forced-prefix 试点门（stage 1 已结算）

> 事后补件。stage 1 于 2026-08-12 10:0x 在 CPU 上跑完；stage 2（GPU 两遍式生成）**未开工**，
> 理由见 §7、§8——试点门的第一道闸就改变了 stage 2 的问题定义。

## 1. 目标指标与基线

- **目标指标**：**几何码捕获率**（对构造侧 GT 码的分组 macro-F1，阈 0.5，D-10 同度量线）
- **基线值**：**无先例**——这是本战役第一次在**码级**度量文本路径。
  此前流通的「词级准确率 82%」是**另一个度量**（词是否出现），D-10 已明令不得与 macro-F1 互换。
  本 EPR 产出的就是 D-10 要求的 `F1_A1` 参照线本身。
- 关联基线（供 EPR-002 判读）：headline mIoU 0.7909。

## 2. 预注册数字（冻结）

| 门 | 数字 | 处置 |
|---|---|---|
| 试点闸 R_json | 解析失败率 **< 0.5%** | 超过 = harness bug，停查 |
| 试点闸 R_trunc | 截断率 **< 0.5%** | 同上 |
| 覆盖率 | ≥70%，否则必须报**覆盖分层 Δ**，禁只报全体均值 | — |
| C 臂规则（§3.2） | 解析臂捕获 Δ_GT 比值 ≥0.7 ⇒ 不立 C 臂 | 由 EPR-001/002 结算 |

## 3. 假设一句话

成功则能说：**模型自生成的 `<where>` 文本里的几何，可被 21 维解析器以可度量的保真度
取出来（并因此值得注入）**；失败则不能说文本路线可部署——但**不能**据此说文本里没有几何。

## 4. 输入

- **local train** 分片，n=**500**（`seed=20260812` 的无放回抽样，`exclude_low=True`，render_mode=local）
- **探针档**（n=500 / 全量 42,752），按纪律如实标注
- 文本来源：`GenContextStore(train)` 缓存的**模型自生成** `<where>` span（159,215 行），
  **不是 GT 文本** ⇒ 度量的是部署分布
- GT 码：`.vrmeta.json` 的 `slot_id` + `region`

## 5. 方法（与既有路径的唯一差异）

stage 1 **不做任何生成**：pass-1 的自生成 span 已被缓存，直接解码→解析→对 GT 码打分。
这是 EPR-002 正在注入的**同一个码**，所以本 EPR 度量的就是 EPR-002 的输入质量。

stage 2（未执行）本应加：复用上下文 + forced prefix `<geom>` 的第二遍复述再解析。

## 6. 判据表（含运行时断言）

| 列 | 规则 | 断言 |
|---|---|---|
| capture_shape | 5 个 shape 槽 macro-F1 | GT 未点亮的槽**从宏平均中剔除**（否则恒 0 的槽把分数拉向 1） |
| capture_dir | 9 个 direction 槽 macro-F1 | 同上 |
| capture_ext | **不可测** | `.vrmeta` 无 extent 字段 ⇒ 6 个 extent 槽 GT 恒 0，硬编码为「不可测」而非 0 分 |
| 弃权率 / 激活位数 | 解析器沉默与过度点亮各自成列 | 随板落盘 |
| **AUC** | 禁 | 不产出 |
